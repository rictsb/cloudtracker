# Compute / Value — tracker

`AI-Infra-Tracker-Spec.md` is the binding contract and source of truth. It overrides any other instinct about structure. When a change isn't covered by the spec, stop and ask. When tempted to add a file, structure, or feature not in the spec, point back to the spec instead.

## What this is

A static web app (HTML / CSS / vanilla JS, no framework) — a first-principles relative-value tracker for AI-infrastructure names. All company and site data lives in `data.json`, loaded at runtime. The app is a Render Static Site; push to `main` auto-deploys.

The valuation engine lives in `engine.js`, the GPU-ramp math in `ramp-core.js`, and the research-report math in `onepager-core.js` (all shared browser + node — never fork the math). Research reports (`/iren`, `/crwv`, `/nbis`, spec §6d–6e) render client-side from `<tk>-data.json`, generated by `node export-research.js <TK>` from the name's `page` + `ramp` blocks in `data.json`; the comparison page (`/research/compare`, spec §6f) renders from `compare-data.json` (`node export-research.js --compare`). Never hand-edit a generated data file. `node verify.cjs` is the pre-push gate for the app layer (render states, engine parity, data freshness) alongside `node checks.js`. Routing rules live in `render.yaml`, mirrored in the Render dashboard. The paper portfolio (spec §6b) is `portfolio-core.js` (allocation), `portfolio-run.js` (daily job, run by the GitHub Action), `portfolio-backtest.js` (regenerates history), `portfolio.json` (state, overwritten daily) and `portfolio-history.json` (the ONE sanctioned time-series ledger). The News and Approvals screens (spec §6, 12–13, §6g) read `news.json` and `proposals.json`, which the DGX Spark pipeline (`~/transcribe/` on the Spark, not in this repo) pushes daily; `proposals-apply.js` is run only by the `apply-proposals` Action after a decision on the Approvals screen — never apply proposals by hand.

## File discipline (spec §10–§11 — hard rules)

1. **State is present-tense only.** No file records "previously X, now Y, updated on…". History lives in `CHANGELOG.md`, nowhere else.
2. **Ticker state is structured data in `data.json`** — fields you overwrite, not markdown. There are no per-ticker files.
3. **Closed allow-list of markdown.** Only these may exist: `CLAUDE.md`, `AI-Infra-Tracker-Spec.md`, `CHANGELOG.md`, (optionally) one `WIKI.md`, and the skill prompt `.claude/skills/one-pager/SKILL.md`. Do not create any other markdown file without asking.
4. **Edit in place, never append.** When state changes, overwrite it and add one line to `CHANGELOG.md`.

## Working rules

- Research pricing follows §6i: shared forward curve, explicit expiring contracts and renewals, sourced versus inferred coverage, matched earning-MW denominators and derived operating multiples. Regenerate all three report payloads after changing pricing. Run `node verify-pricing.cjs`, `node verify-pricing-checks.cjs` and `node verify-pricing-finance.cjs` alongside the existing gates.

- The 2026-09 redesign (single-page app: `index.html` + `app.js` + view modules + `styles.css`/`report-layout.css`) is the reference design; rebuild into its system, don't re-invent per screen.
- Before every push, verify the app actually works. Never push a broken build.
- Small, frequent commits, conventional messages. Use `[skip render]` for commits that shouldn't deploy (spec/changelog edits).
- Keep this file terse and present-tense.
